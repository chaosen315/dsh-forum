# 05 · 调研里有三个建议，只采纳其中一个

你让 Agent 比较了几种办法。接下来希望采纳其中一项，同时保留“为什么选它”和“另外两项为什么暂缓”。

准备：[建立练习库](README.md#建一个独立练习库)，打开 `lab-research`。输入 [options.md](materials/options.md) 列出三种**虚构方案**及本次需求，不涉及真实产品排名。

## 第一条委托：形成可决定的结论

```text
@执行者 根据本帖和 materials/options.md，
比较三种给新同事交接工作的办法。
目标：离线可读，只交接我选定的帖子，还能回查结论来源。

请把事实、由事实得出的判断、尚未验证的假设分开。
推荐一项最小方案，列出暂缓项和理由；回本帖等待我作取舍。
本轮不生成交接包、不改项目或插件。
```

预期判断：本题适合 **B「选定帖摘要 + 来源索引」**。A 整库快照能离线，但超出了所选内容；C 托管门户要求网络且引入服务运维。B 的摘要容易过期，需要保留来源的 post ID / answer ID 以及制作时间，后续按来源重新核对。报告不能把这些材料写成实际产品测试结论。

## 第二条委托：把你的取舍变成任务

决定采纳 B 后，在调研结果下发送：

```text
@执行者 采纳 B，只做一次本地交接摘要；A、C 暂缓。
请新建执行帖，引用本帖当前调研 answer，并把新帖链接回这里。
我授权你继续执行新帖，不必再询问是否开始。

执行背景：本次采纳的调研结论，以及 project-guide、project-copy 的 head。
交付 handoff/selected-notes.md，只包含这两帖的标题、目标、当前结果、
未决事项、post ID、answer ID 和本次制作时间。
引用已读内容，不复制整个库或其他帖子；不修改这两条来源帖。
验收：恰好两条记录，来源锚点存在，内容与当前来源一致。
检查失败则在此文件范围内修正；结果回执行帖，摘要链接回调研帖，等待我验收。
```

这条评论已同时授权“建立任务”和“继续执行”。新帖的 `depends_on` 应记录调研 answer 及两个来源帖；如果使用 UI 建帖，先补首条 answer 作为委托锚点，再按需要派活。不要仅仅建完帖就宣称有人开始工作。

## 你如何验收

1. 从调研帖进入执行帖，确认只采纳 B，A/C 仍暂缓。
2. 打开练习目录的 `handoff/selected-notes.md`，确认只有 `project-guide`、`project-copy` 两条记录。
3. 分别用 `node tools/kb.js view project-guide --scope head --comments none`、`node tools/kb.js view project-copy --scope head --comments none` 核对；初始来源都是 `a1`，后续做过练习则以真实 current 为准。
4. `project-guide` 应仍表达待验收；`project-copy` 应保留已接受依据。摘要应包含制作时间，不能把等待验收改写成已完成。

之后如果你只退回摘要中某一项，反馈落到执行帖即可；调研结论保持，必要时只更新关联结果。回退时可移除本次新文件，任务及选择记录留在帖子中。
