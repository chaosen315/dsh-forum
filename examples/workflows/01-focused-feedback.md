# 01 · 大部分通过，只改需要修正的部分

你已经收到一份说明，第一、三行都不错，第二行夸大了平台支持范围。把反馈留在这份结果旁边，下次回帖即可看修订。

准备：[建立练习库](README.md#建一个独立练习库)，打开 `lab-feedback`。材料是 [feedback-note.txt](materials/feedback-note.txt)，三行草稿已放在练习目录。这里的“便签盒”是虚构产品。

## 发出这条委托

在 `lab-feedback` 当前 answer 下选择真实执行目标，再发送：

```text
@执行者 第一行和第三行通过，逐字保留。
请只修改 materials/feedback-note.txt 的第二行：
将“全平台即装即用。”改为“已验证 macOS；其他平台待验证。”
背景仅限本帖与该文件，结果继续回本帖。

验收：文件仍恰好三行；第一、三行不变；第二行与上述文字完全一致。
请在练习目录运行 node examples/workflows/check-result.js feedback，
把实际输出、文件位置、修改理由写进新 answer，等待我验收。
如果检查失败，只修这一个文件并复验；不要扩写文案或修改检查器。
```

确认「已派」回执后，可以关掉 session。这个委托同时交代了保留项、修改项、验证方法和结束条件。

## 回来检查

在练习目录运行：

```bash
node examples/workflows/check-result.js feedback
node tools/kb.js view lab-feedback --scope head --comments none
```

初始文件的检查结果应为非零退出；修改正确后应输出 `PASS feedback`。文件应是：

```text
便签盒：让零散想法有处可放。
已验证 macOS；其他平台待验证。
先试用，再决定是否保留。
```

current 应包含这份**完整结果**、检查的实际输出和“等待验收”，而不只是“已改第二行”。检查器只验证文件，不证明 Agent 已回帖，也不验证虚构产品的平台能力。

如果第一行被顺手重写，在该结果下点名反馈：

```text
@执行者 第二行通过。第一行应恢复为“便签盒：让零散想法有处可放。”
请保留其余已通过内容，复跑原检查，并将完整结果回到本帖。
```

通过后，明确留言“我已按检查步骤验收，通过”，需要收尾则再次点名执行者，让其记录接受依据和完成状态。

## 换成自己的工作

同样适合改一段发布说明、修一个表格字段或退回某条测试结果。把“逐字保留的部分”和“失败后允许继续修改的范围”说清。文件回退只需恢复本次改动行；帖子中的旧答复保留，用新 answer 更正。
